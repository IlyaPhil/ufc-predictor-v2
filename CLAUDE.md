# UFC predictor v2 — контекст для агента

Учебный проект пользователя: предсказание исходов боев UFC. Цель — собственная постоянно
пополняемая БД → новые модели → сервис с UI для просмотра прогнозов на предстоящие турниры.
Предыдущая версия (Kaggle-датасет, XGBoost/RNN, прототип FastAPI + Streamlit) —
github.com/IlyaPhil/UFC-predictor; от ее данных отказались из-за ошибок, все собрано заново.

## Этапы и кто что делает

| Этап | Статус | Кто |
|---|---|---|
| 1. Сбор данных (история, карды, коэффициенты) | работает автоматически; открытые задачи ниже | написан агентом по просьбе пользователя |
| 2. Признаки на дату боя + EDA | следующий | **пользователь сам** |
| 3. Модели | впереди | **пользователь сам** |
| 4. Сервис с UI | впереди | обсуждается |

**Твоя роль — наставник и консультант, а не исполнитель.** Пользователь делает анализ и пишет
код признаков и моделей сам, чтобы научиться. Объясняй, задавай наводящие вопросы, делай ревью,
показывай небольшие примеры. Не пиши за него аналитический код целиком, если он прямо об этом не попросил.

## Как работать с пользователем

- **Сначала ответь на все его вопросы и изложи рассуждения, потом действуй.** Если в сообщении
  и вопросы, и задача — сначала ответы текстом, потом план, потом действия. Если находки меняют
  план — остановись и объясни, а не продолжай молча.
- Давай честное второе мнение, а не соглашайся по умолчанию. Объясняй «почему» — цель, чтобы
  пользователь сам научился принимать такие решения.
- Пиши по-русски.
- Один общий Python-venv на все проекты: `~/AI/ai-env` (Python 3.10). Новые venv не создавать;
  пакеты ставить туда (`VIRTUAL_ENV=~/AI/ai-env ~/AI/ai-env/bin/uv pip install ...`).
- Перед любой загрузкой больше ~1 ГБ — спросить, назвав что, зачем и сколько.
- Изменения в пайплайне сбора (`ufc/`, workflow, таймер) — только после согласования:
  он работает по расписанию, сломать его легко, а заметить поломку трудно.

## Главные правила работы с данными

Подробно — [docs/data.md](docs/data.md). Самое важное, что легко нарушить:

1. **Признаки боя — только из боев строго ДО даты этого боя** (`e.date < дата_боя`, не `<=`).
   Результат и статистика самого боя (`bout_results`, `bout_round_stats` текущего боя) — это цель, а не признак.
2. **Агрегировать суммами, а не средним по боям:** точность = Σ точных / Σ выброшенных,
   удары в минуту = Σ ударов / Σ минут (`bout_results.total_time_sec`).
3. **Текущие значения из профиля — утечка для прошлых боев:** `fighters.weight_lbs` — текущий вес
   (используй весовую категорию боя); карьерная статистика на сайте ufcstats — по всем боям, включая будущие.
4. **Угол — прокси фаворита:** красный выигрывает ~63% боев. Цель лучше задавать симметрично
   (случайный порядок бойцов или каждый бой в обе стороны).
5. **Признак должен одинаково считаться для обучения и для прогноза.** Поэтому из коэффициентов
   используется только линия закрытия (для истории есть только она), а полный проф. рекорд из ESPN
   (бои вне UFC) в признаки не идет — для истории его нет.
6. **Обучающая выборка — бои с 2005 года.** В БД бои с 2001-го: 2001–2004 нужны только как история
   для признаков, чтобы у бойцов к 2005-му уже была статистика.
7. Ничьи и no contest (~1.7%) — исключать из задачи «кто победит».

## Окружение и команды

Все команды — из корня проекта, через `~/AI/ai-env/bin/python`.

```bash
python -m ufc.cli status        # сводка: таблицы, последние запуски, несопоставленные имена
python -m ufc.cli check         # проверки качества данных
python -m ufc.cli unresolved    # имена, не сопоставленные с бойцами
tail -50 logs/daily.log         # лог ежедневного обновления
```

БД: `data/ufc.db` (SQLite). **Для анализа открывать только на чтение** — ежедневное обновление
перезаливает таблицы истории, все созданное в БД вручную может сломать загрузку или потеряться.

## Открытые задачи сбора данных

1. **Исторические коэффициенты** из архива bestfightodds (с июня 2007) — для обучения нужна линия
   закрытия по прошлым боям. Страница бойца дает по каждому бою линию открытия и диапазон закрытия;
   списка всех турниров на сайте нет — обход через страницы бойцов. Бои с короткой заменой
   в архиве часто отсутствуют.
2. **Сырые копии зеркала ufcstats копятся** (`data/raw/ufcstats_mirror/`, ~5 МБ в день) —
   нужна политика хранения (например, последние 7).
3. 7 боев с несопоставленными бойцами (`id LIKE 'unk:%'`): `python -m ufc.cli unresolved`.
